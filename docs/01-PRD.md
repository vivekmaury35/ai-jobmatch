# AI JobMatch — Product Requirements Document (PRD)

## 1. Product Summary
AI JobMatch is a web application that compares a candidate's resume against a specific job description and produces an **explainable** match score — not a single number the LLM invented, but a score built from deterministic skill matching, semantic similarity, and structured reasoning, with a plain-language explanation of why the score is what it is.

The product exists to (a) genuinely help a job seeker see gaps before applying, and (b) serve as a technically credible portfolio project the builder can defend line-by-line in an interview.

## 2. Problem Statement
Job seekers apply to roles without knowing how well their resume actually matches the requirements. Existing "resume checkers" either do dumb keyword counting (miss synonyms: "Postgres" vs "PostgreSQL") or blindly ask an LLM for a score (unexplainable, inconsistent between runs, easy to game, not defensible as an engineering artifact).

## 3. Target User
- Primary: the builder himself, using it on real job applications.
- Secondary (demo audience): recruiters/interviewers evaluating the builder's engineering ability via the live app + GitHub repo.
- This is **not** being built as a multi-tenant SaaS product. Single-user-per-session is fine for MVP.

## 4. Goals
1. Produce a match score that is reproducible: same resume + same JD → same score every time.
2. Make the score explainable in plain language (what matched, what's missing, why it matters).
3. Ship a working end-to-end vertical slice fast, then layer polish — not a beautiful UI wrapped around a fake score.
4. Every technical decision must be answerable in an interview ("why FastAPI," "why not let the LLM score it," etc.)

## 5. Non-Goals (explicitly out of scope)
- Multi-user accounts, billing, payments, teams
- Public production-scale deployment / high concurrency
- Job board scraping (LinkedIn/Indeed scraping)
- Mobile app
- Kubernetes / microservices / message queues
- Real ATS integration or claiming ATS-certified compatibility (use the phrase "ATS-style keyword analysis" only)

## 6. Core User Flow (MVP)
1. User opens the app (no login required — a lightweight session/device ID is enough to scope "my saved jobs").
2. User uploads a resume (PDF).
3. User pastes a job description (plain text).
4. User clicks "Analyze."
5. App parses both, computes the hybrid match score, and shows:
   - Overall score + sub-scores (skills, semantic, experience)
   - Matching / missing / partially-matching skills
   - A short natural-language explanation
   - 2–4 concrete resume improvement suggestions
6. User can save the analysis and see a simple history list.

## 7. MVP Feature List (Must-Have)
- Resume PDF upload + text extraction
- Job description text input
- Structured extraction of resume sections (skills, experience, education, projects) — LLM-assisted, schema-validated
- Structured extraction of JD requirements (required vs preferred skills, experience years, education)
- Skill normalization (alias dictionary: "Postgres" → "postgresql", etc.)
- Hybrid match engine: rule-based skill scoring + embedding-based semantic similarity, weighted into one score
- Three-tier skill matching: exact / alias / related
- Explanation panel generated by LLM strictly from the computed scores + extracted evidence (LLM does not invent the score)
- Resume improvement suggestions (evidence-based, no invented achievements)
- Save analysis + simple list of past analyses (job title, score, date)
- Basic error handling: unparseable PDF, too-short JD, network/API failure

## 8. Phase 2 Feature List (Should-Have, after MVP works)
- Radar chart visualization of sub-scores
- Skill gap matrix table
- Evidence drill-down per skill ("why is this marked missing")
- ATS-style keyword coverage report
- Resume Quality Score (independent of any specific JD)
- Recruiter Summary generator
- Analysis caching (same resume+JD hash → skip re-computation)

## 9. Future / Nice-to-Have (not planned, don't build)
- AI-generated cover letters
- Resume version history / diffing
- Browser extension for capturing JDs
- Interview-prep question generator
- OmniRoute-based multi-provider AI routing (see Architecture doc §7 — optional swap-in, not required for MVP)

## 10. Success Criteria
- Can run a real resume + real JD through the full pipeline and get a score that the builder can explain field-by-field.
- Score is reproducible across repeated runs on the same inputs.
- Full flow (upload → paste JD → analyze → see results) completes in under ~15 seconds on typical inputs.
- Deployed and reachable via a public URL for portfolio/recruiter use.
- README + architecture diagram exist and the builder can explain every box in the diagram.

## 11. Constraints
- Zero/near-zero budget: must run on free tiers (Gemini API free tier, free Postgres instance, free/low-cost hosting).
- Builder is not writing code by hand — Claude Code will implement from these docs, so every requirement here must be unambiguous enough to hand directly to an AI coding agent.
- Local embeddings via Sentence Transformers preferred over paid embedding APIs to keep cost near zero.

## 12. Open Questions (resolve before Phase 2)
- Do we need DOCX support for MVP, or PDF-only? (Recommendation: PDF-only for MVP, add DOCX in Phase 2.)
- Single hosted demo resume/JD pair for the portfolio, or must every visitor be able to upload their own? (Recommendation: allow real uploads — it's more impressive and barely more work.)
